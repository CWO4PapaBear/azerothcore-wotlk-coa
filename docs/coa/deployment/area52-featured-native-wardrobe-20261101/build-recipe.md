# Native Wardrobe reuse correction

Owner screenshots show the previous approximation still misplaced/scaled the model and left most assigned rewards empty. This source changes only existing EditableBuildView.lua. Installed source baseline is the activated Wardrobe editor package; all other MPQ members and prior corrections remain byte-identical. No new addon/DLL, server binary or SQL.

Reuse AppearanceCategorySlotButtonTemplate directly, including its43px size, border/no-item atlas and actual item-icon rendering methods. Override interaction/event callbacks to edit build rewards only: no Apply Transmog, purchase, redemption or player-equipment mutation. Load the existing Appearance UI before template creation. Use actual ModelMixin setup/drag/zoom and AppearancePlayerModelMixin.InternalUndress/Dress, with getters redirected to build item assignments. Native380x538 geometry/background and slot anchors are retained; body/tabard/illusion controls are omitted because they are not reward slots. Mounts stay separate.

The canvas is a direct child of the editor ScrollFrame, not its scrolling Content. Its anchors track the reward section; available viewport height determines uniform scale. Visibility compares actual effective-scale coordinates and hides the complete canvas when it crosses viewport bounds. This avoids inheriting the scroll-child model transform and prevents model/buttons escaping over other sections. It does not modify the actual Wardrobe frame or installed client. Live graphical acceptance at the owner's UI scale/race is still required; offline tests cannot certify native rendering.

Item import previously assumed item-set list keys were equipment slots. The corrected importer sorts the list for deterministic weapon ordering and classifies each resolved item by native InventoryType. Armor uniquely maps to its reward slot, generic one-hand weapons fill main then off hand, invalid/relic records are excluded, and existing two-hand protection remains. Existing saved choices, including deliberate empty slots, are not silently overwritten. A previously partially imported build needs Load archetype set then Save; earlier metadata cannot distinguish deliberate empty slots from failed import. New imports use the corrected classifier automatically.

ui-r2/report.json passes the prior regression suite plus native Wardrobe model/slot functions, viewport parentage/clipping/effective-scale tests and reordered complete-armor import. Actual model/shared/slot Lua definitions are executed with bounded frame/engine adapters. Captured reference hashes are in reference.json. This is offline engineering evidence, not live graphical certification. Release/package/CheckOnly results are recorded separately when complete; nothing is activated by preparation.
